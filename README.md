A professional-grade, automated retrieval pipeline designed for Data Science, Machine Learning, and Business Intelligence workflows. This module ensures secure, rate-limited extraction from global data sources prior to downstream analysis.

## 1. High-Level Architecture & Value Proposition

The pipeline is architected to optimize developer velocity while maintaining strict data integrity and operational security.

- **Zero-Imputation Data Purity:** Data is preserved precisely as served by the upstream source. The pipeline acts strictly as a retrieval and normalization layer, enforcing raw extraction without unauthorized data cleaning or unapproved imputation.
- **Dynamic Format Normalization & Automated Markdown Profiler:** The extraction engine natively resolves data payloads and standardizes the output schema. Upon successful extraction, an automated markdown profile (`<dataset_name>_description.md`) is dynamically generated, detailing metadata summary, data preview, null-density distributions, column data types, and numerical statistics.
- **Secure Configuration (Lazy-Loaded State):** Eliminating insecure shell-based `.env` population, the pipeline now manages credentials via an isolated, OS-standard JSON configuration file (`~/.config/data-fetcher-pipeline/config.json`). This mitigates vulnerability flags generated by static application security testing (SAST) tools like Snyk and Socket. Credentials are fundamentally lazy-loaded and only evaluated at execution time for specific target endpoints.
- **Operational Efficiency:** Substantial reduction in manual boilerplate code, payload parsing, and repetitive directory configuration.

## 3. Deep Technical Guide

### Installation Strategy

The pipeline is packaged natively. This automatically resolves dependencies and exposes the `data-fetcher` executable to your system path.

**Package Installation:**
```bash
pip install .
```

```bash
data-fetcher --source openml --query "finance"
```
Or execute the script interface directly:
```bash
python scripts/cli.py --source openml --query "finance"
```

#### OpenML Interactive Strategy
The pipeline integrates `openml` for CLI-based intelligent lookup. The `OpenMLFetcher` resolves text queries (e.g., "iris") against the OpenML global index with relevance ranking: an **exact name match always wins**, otherwise the **smallest** matching dataset is preferred (search is for exploration — the biggest match is usually a bloated mirror). Ranked candidates (name, dataset ID, rows × features) are displayed for interactive selection, and a size budget automatically skips oversized candidates. A **numeric query targets a dataset ID directly** (e.g. `--query 61`), bypassing search entirely.

### Containerized Execution (Docker)

When running the pipeline within a Docker container, downloaded files will be written to an isolated filesystem unless you map a volume to your host machine. Credentials are read from the global config JSON or environment variables — mount your config and output directory:

```bash
docker run \
  -e FRED_API_KEY=<your_key> \
  -v ~/.config/data-fetcher-pipeline:/root/.config/data-fetcher-pipeline \
  -v ~/Desktop:/output \
  your-docker-image-name
```

| **CoinGecko** | `coingecko` | Cryptocurrency price, market cap, and volume history — no API key required. | Crypto analysts tracking digital-asset market history. |

**Pacing & Rate Limits:** requests are paced per provider in every mode — a per-host minimum-interval table in `http_utils` (e.g. CoinGecko ≥ 6s) is enforced for agents and humans alike, `Retry-After` headers are honored (capped at 60s), and interactive runs additionally impose a 2–5s humanized delay. Every fetch discloses its exact provider spend (`provider_requests`, `retries`, `bytes_transferred`) in the JSON envelope.

**Performance Characteristics:** downloads stream to disk with a hard byte cap (memory-flat regardless of payload size), Excel export uses openpyxl write-only streaming with a 16,384-column guard, dataset saves are atomic (temp file → fsync → single `os.replace`, with self-healing recovery), and discovery commands skip the data stack entirely (~0.2s startup).

### Architectural Assessment

**Cross-Platform Package Strategy:**
Deploying as a native Python package (`pip install .`) resolves dependencies cleanly and exposes the `data-fetcher` console script globally. The legacy `run_pipeline.sh` bash-wrapper was removed to eliminate POSIX shell incompatibilities on Windows environments and logic duplication. The pure-Python CLI and zero-arg interactive wizard cover 100% of user workflows cross-platform.

**Data Source Efficacy:**
The pipeline natively supports 11 platforms across 12 CLI keys, covering machine learning (OpenML, Kaggle), corporate finance (SEC), macroeconomics (FRED, World Bank, Eurostat), crypto markets (CoinGecko), search directories (Data.gov, GitHub), and scraped web directories (Airbnb) — with provider-pushed row limits, per-host pacing, and atomic provenance-tracked saves on every fetch.

## 4. Recent Updates

- **Trust Contract Remediation (multi-agent audit-driven)**: atomic writes with `.prev` retention and append-only `manifest.jsonl` provenance (sha256, truncation, warnings); coded JSON error envelopes with stable error codes and guaranteed startup envelope (exit 3); lazy provider registry isolating broken optional dependencies; cost metering (`provider_requests`/`retries`/`bytes_transferred`) in every envelope; provider-pushed `--rows N` row limits; cheap one-request previews; WorldBank pagination hardening (page-echo validation, partial-as-degraded); per-host rate pacing in all modes; SSRF/robots hardening on custom URLs; masked credential entry; corrupt-config surfacing.
- **Performance**: streamed downloads (memory-flat at any payload size), openpyxl write-only Excel export, column-bounded markdown profiling, lazy data-stack imports (~0.2s discovery startup).
- **Kaggle & SEC EDGAR Architecture Integration**: Fully implemented native extraction classes `KaggleFetcher` and `SECFetcher`. Configuration handling has been securely routed through the global state validation layer to prevent crashes.
- **Cross-Platform Path Unification**: Removed all hardcoded absolute paths and shell dependencies. Directory provisioning is now 100% native Python, ensuring absolute compatibility across Windows, macOS, and Linux without fragile POSIX shell fallbacks.
- **Format Alchemy ETL Module**: Deployed an isolated post-processing transformation engine (`scripts/format_alchemy.py`). Converts raw CSV payloads into SQLite databases, Parquet, JSON, and auto-formatted Excel workbooks on demand (`--convert FORMAT FILE` or the interactive prompt), without violating the core "Pure Fetcher Philosophy".
